# tuto — 유튜브 튜토리얼을 "따라 할 수 있는 문서"로 바꾸는 Claude Code 플러그인

`/tuto <video-url>` 한 줄이면, 영상의 **설정값·버튼명·조작 순서**를 화면에서 직접 읽어 스텝별 가이드를 만듭니다.
모든 값에는 근거 프레임 타임스탬프가 붙고, 독립 감사 에이전트가 반박을 시도한 뒤에야 사용자에게 제시됩니다.

> **English TL;DR** — A Claude Code plugin that turns a YouTube tutorial into a step-by-step guide.
> It runs a two-pass, signal-weighted frame sampler (heatmap · chapters · activity curve · caption cue words),
> reads settings and button labels **from the screen** rather than from captions, and verifies every claim with
> independent adversarial audit agents before showing you anything. Korean/English videos, ≤30 min.

## 왜 만들었나 — 자막만 믿으면 틀린다

튜토리얼 영상에서 정작 중요한 값은 **말로 하지 않습니다.** 화면에만 있습니다.

실제로 겪은 사례입니다:

| 자막이 말한 것 | 화면에 있던 것 |
|---|---|
| "윈도우는 `python`" | 화면에는 **`python3`** 타이핑 (사용자 실측 결과 화면이 맞았음) |
| "슬로우다운 98배" | 슬라이드에는 **`0.98배`** (한국어 ASR이 소수점 누락) |
| "16배 차이" | 슬라이드 카드는 **`16.3x`** (90,991 vs 5,584) |
| "600 팔로워" | 화면에는 **`576`** |
| "민간임대" | 영어 자동번역 자막은 *"private lattice housing"* |

`tuto`는 **자막과 화면이 다르면 화면을 채택**하고, 불일치를 각주로 남깁니다.
화면에서도 읽히지 않으면 추측하지 않고 `⚠️ 화면 확인 필요`로 표시합니다.

## 설치

```bash
claude plugin marketplace add dingmon1019/YoutubeAnalyzer
```

```bash
claude plugin install tuto@yta
```

설치 후 Claude Code를 재시작하면 `/tuto`가 스킬 목록에 나타납니다.

**업데이트** (`install`은 이미 설치된 플러그인에 동작하지 않습니다):

```bash
claude plugin update tuto@yta
```

### 요구사항

| | 설치 예시 |
|---|---|
| Python 3.11+ | — |
| ffmpeg / ffprobe | `winget install Gyan.FFmpeg` · `brew install ffmpeg` |
| yt-dlp | `pip install -U yt-dlp` |
| (선택) faster-whisper | `pip install faster-whisper` — 로컬 ASR 폴백 |

세션에서 `/tuto`를 처음 호출하면 프리플라이트가 자동으로 점검하고, 빠진 항목의 설치 명령을 안내합니다.

### 설정 (선택)

자막이 아예 없는 영상만 ASR이 필요합니다. `~/.config/yta/.env`가 첫 실행 시 자동 생성됩니다.

```ini
GROQ_API_KEY=          # console.groq.com/keys — 비우면 로컬 faster-whisper로 폴백
CACHE_MAX_VIDEOS=10    # video.mp4를 유지할 최대 영상 수 (LRU)
```

키가 없어도 동작합니다 — Groq → 로컬 whisper → 프레임 중심 분석 순으로 자동 폴백합니다.

## 어떻게 동작하나

```
패스1 (지도)          패스2 (확대)              작성                검증
─────────────        ──────────────           ────────           ────────
analyze.py           판독 에이전트 →           가이드 빌더        표본 감사 6건
 ├ yt-dlp 다운로드    zoom-plan.json            (sonnet)           (sonnet, 독립 컨텍스트)
 ├ 원어 자막 2단계     ├ 자막 지시어 큐            ├ 프레임 판독        ├ "이 주장을 반박하라"
 ├ 히트맵·챕터        ├ 챕터 경계               ├ --crop 재확대      ├ MISMATCH → 상위 모델 재검
 ├ 활동곡선 55피크     ├ 활동 피크 커버          └ guide.md         └ 커버리지 감사(누락 검출)
 └ 지도 프레임         └ 프레임 공백 탐지
```

**1. 신호 가중 프레임 선정** — 무작정 등간격으로 자르지 않습니다.
유튜브 **히트맵**(많이 본 구간), **챕터 경계**, **활동곡선 피크**(말 없는 조작 방어),
그리고 **자막 지시어 큐**("여기 보시면", "클릭", "look here", "this setting")가 겹치는 지점에 프레임을 배정합니다.

**2. 해상도 티어링** — 글자를 옮겨 적어야 하는 화면(슬라이드·표·조건식·메뉴·터미널)만 1024px,
삽화·토킹헤드는 512px. **지도 프레임으로 못 본 지점은 무조건 1024** — 텍스트가 없다는 걸 확인할 수 없기 때문입니다.

**3. 프레임 공백 탐지** — 지도 프레임이 60초 이상 비는 구간을 찾아 우선 배정합니다.
튜토리얼의 **"제대로 됐는지 확인하는" 마지막 구간**은 화면 변화가 적어 프레임 선정에서 구조적으로 탈락하는데,
정작 따라 하는 사람에겐 성공 판정 기준입니다. 실측 2건에서 결론부가 통째로 누락된 걸 확인하고 규칙으로 넣었습니다.

**4. 독립 감사** — 가이드 본문을 주지 않고 **주장 1개 + 근거 프레임만** 새 에이전트에 보내
*"이 프레임을 읽고 주장을 반박하라"*고 시킵니다. 확증 편향을 구조적으로 차단합니다.
불일치가 나오면 그 주장만 상위 모델로 다시 검증합니다.

**5. 커버리지 감사** — 자막·챕터에서 "기대 스텝 체크리스트"를 **먼저** 만들고,
가이드 스텝 제목과 대조해 빠진 걸 찾습니다. 표본 감사가 구조적으로 못 잡는 *누락*을 담당합니다.

## `watch` 같은 범용 영상 스킬과 뭐가 다른가

같은 영상(부동산 청약 안내, 16:11, 한국어 자막)으로 실측 비교한 결과입니다.

| | watch (범용) | tuto |
|---|---|---|
| 프레임 | 100장 @512px | 54장 (512×41 + **1024×13**) |
| 임대조건 표 구간 | **0장** — scene-change가 정지 문서를 스킵 | 포착 |
| 자막 | 영어 **자동번역** 트랙 선택 | ko **원어**, 롤링 중복 759건 제거 |
| 금액·소득기준 표 | 512px에서 **판독 불가** | 1024px로 전부 추출 |
| 프레임 예산 | 100장 중 ~55장이 집 구경 구간 | 지시어·챕터·피크 가중 배정 |
| 검증 | 없음 | 표본 감사 6 + 커버리지 1 |

**핵심 차이는 "무엇을 볼 것인가"를 정하는 방식입니다.**
장면 전환(scene-change)으로 프레임을 고르면 **정지된 문서 화면이 통째로 스킵**됩니다.
그런데 튜토리얼에서 값이 적혀 있는 곳이 바로 그 정지 화면입니다.

> 이 비교는 tuto v0.1.0 시절 측정치입니다. watch의 위 특성은 구조적인 것이라
> 이후에도 유효하지만, 절대 수치는 두 도구 모두 갱신됐을 수 있습니다.
> watch는 "영상을 폭넓게 훑는" 용도로는 여전히 유효하고 훨씬 쌉니다 — 목적이 다릅니다.

## 어떻게 발전시켰나 — 4라운드, 전부 실측 게이트

각 라운드는 **"품질 비저하"를 증명하지 못하면 롤백**한다는 규칙으로 진행했습니다.

| 라운드 | 한 일 | 실측 결과 |
|---|---|---|
| **R1** 성능 | 스크립트 병렬화, 감사 모델 3파전 | analyze 154→19초, zoom 327→61초. 감사는 **sonnet+크롭** 채택(에스컬레이션 0%) |
| **R2** 품질 | 커버리지 감사 신설, 서식변화 검증, `--crop` 재확대 | 오류주입 검출 성공. **OCR 레버는 게이트 미달로 롤백** |
| **R3** 비용 | 가이드 작성을 sonnet 빌더에 위임 (하이브리드 티어링) | 값 33/33 동일, 서사 동등 |
| **R4** 비용·품질 | 오케스트레이터 컨텍스트에서 **이미지 완전 제거** | 본체 `cache_write` **−95%**, 전체 **−27%**, 품질 순증 |

### 배운 것 중 남길 만한 것

- **OCR은 이 도메인에서 안 됩니다.** winocr 1024px에서 26개 중 4개, tesseract(+kor) 6개.
  영상 압축된 한글 잔글씨는 OCR 불가 도메인이고, VLM 직접 판독(70/70)이 압도적이었습니다.
  게이트 기준 95%에 한참 못 미쳐 **구현해 놓고 롤백**했습니다.
- **검출력 게이트 통과 ≠ 실전 성능.** haiku 감사는 오류주입 3/3을 검출했지만 실전에서
  `UNVERIFIABLE`·과잉 반박이 쏟아져 에스컬레이션률 50%였습니다. sonnet은 0%.
- **선명한 프레임을 받을수록 "빈칸 메우기"가 늘어납니다.** 흐린 프레임은 크롭해 뜯어보느라
  빈칸을 알아채지만, 잘 읽히는 프레임은 술술 읽으며 자막으로 메웁니다.
  → 표는 화면 칸 그대로 옮기고, 빈 칸은 `(아이콘만)`, 자막에서 온 건 표 밖 `자막 출처:`로 분리하는 규칙 추가.
- **자기보고형 게이트는 보고자가 세지 못한 걸 잡지 못합니다.** "텍스트 화면 N개 중 N개 1024" 검사가
  통과했는데도 오류가 났습니다 — 못 본 화면을 텍스트 화면으로 셀 수 없었기 때문입니다.
  → 관측 여부(`observed`)를 산출물에 노출시켜 해결.
- **비용 비교는 집계 범위부터 맞춰야 합니다.** 서브에이전트만 센 수치와 전체 수치를 비교해
  "8.6배 증가"라는 잘못된 결론을 냈다가, 동일 방법론으로 재측정하니 실제로는 **절반으로 감소**였습니다.

## 검증 도구

### 비용 집계

```bash
python docs/eval/measure-cost.py --marker VIDEO_ID
```

세션 로그에서 실행 1건의 토큰 비용을 본체/서브에이전트로 나눠 집계합니다.
집계 규약(`message.id` dedup, 달러 가중)이 코드에 고정돼 있어 재현 가능합니다.

### 골든셋 평가

사용자가 **직접 따라 해 본** 튜토리얼로 정답지를 만들어 회귀 기준으로 씁니다 —
[`docs/eval/golden-set-protocol.md`](docs/eval/golden-set-protocol.md).

- **스텝 재현율 (R1-Recall)** — 해야 할 동작을 빠뜨리지 않았는가
- **값 정확도 (Value-F1)** — 조작값(따라 하면 내 화면에도 나타나는 것)과
  인용값(저자 실적 수치)을 분리 집계

## 한계

- **≤30분** 영상 기준입니다. 초과 시 구간 지정을 제안합니다.
- 조작 튜토리얼이 아닌 **전략·개념 설명형** 영상도 처리되지만, 이때 산출물은
  "조작 순서"가 아니라 "슬라이드에 적힌 규칙·수치"입니다.
- 가이드가 검증하는 것은 **"영상이 말한 것과 화면이 일치하는가"**이지
  **"그 내용이 사실인가"**가 아닙니다.
- 프레임에 없는 값은 채우지 않습니다. `⚠️` 표시가 남는 건 실패가 아니라 설계입니다.
- Windows에서 개발·검증했습니다. macOS/Linux는 경로 처리만 다를 뿐 동작해야 하지만 미검증입니다.
