## 목표 대비 결과 — 목표 미달, 정직하게 기록

설계 문서(§0)의 원래 목표는 **달러 기준 4~5.5배 절감** ($11.12 → $2.0~2.8)이었다. 레버 3종(L1 본체 모델 티어, L2 콜 수 통제, L3 표본 축소) 중 **L1은 실측에서 반증되어 최종 비교에 반영되지 않았다** (아래 "측정 시행착오" 참고). 실제로 채택·측정된 것은 L2 + L3뿐이고, 그 결과는:

| 구분 | 개선 전 (v0.3.3) | 개선 후 (라운드5, L2+L3만) | 변화 |
|---|---:|---:|---:|
| **실제 청구** | $11.12 | **$9.96** | **-10.4%** |

목표 구간($2.0~2.8)에 크게 못 미친다. 원인은 본체를 opus로 고정한 채 측정했기 때문이다 — 원래 설계가 기대한 절감의 대부분(본체 $7.20 → $1.44 추정)은 본체를 sonnet으로 낮춰야 나오는데, 그 레버는 실측에서 안정적으로 재현되지 않았다(아래 참고). **이 라운드는 "4~5.5배 절감"이 아니라 "콜 수 통제로 서브에이전트 비용을 거의 절반으로 줄였지만, 본체 자체 비용 증가가 그 절감의 상당 부분을 되돌려 순 효과 -10.4%에 그쳤다"는 결과다.**

## 품질 게이트 — 도구 FAIL, 컨트롤러 실질 PASS 재정

`docs/eval/compare-evidence.py`로 개선 전·후 `evidence.json`을 대조한 게이트 도구는 **값 불일치 1건으로 FAIL**을 냈다. 그 1건을 원본 프레임까지 다시 확인한 결과, 화면의 체크마크 표기가 개선 전에는 `✓`, 개선 후에는 `[선택됨]`으로 바뀐 차이였다 — **판독된 내용(선택 상태)은 동일**하고 표기 방식만 갈렸다. `compare-evidence.py`의 `_semantic_key()`는 기호(`✓`)는 정규화 과정에서 제거되고 한글(`선택됨`)은 남기 때문에 두 표기의 정규형이 달라져 오탐이 났다.

**컨트롤러는 이를 실질 PASS로 재정했다** — 진짜 값 오독 0건이라는 사실은 원본 프레임 대조로 확인됐고, 표기 방식 차이까지 흡수하도록 정규화를 넓히면 진짜 오독까지 함께 흡수할 위험이 커지므로 도구는 그대로 두고 이번 건은 사람이 판정하는 편을 택했다. **이 사실을 숨기지 않고 그대로 기록한다** — 게이트 도구가 "PASS"를 출력하지 않았다는 것과, 그 판정을 사람이 뒤집은 근거 둘 다 남긴다.

다른 실측 회차에서는 게이트가 정당하게 FAIL을 낸 사례도 있었다(아래 "측정 시행착오" 3차 실측 참고) — 도구가 무조건 관대하게 판정하도록 바뀐 것은 아니다.

## 측정 시행착오 — L1(본체 sonnet)이 반증된 경위

목표 달성을 위해 총 4차례 실측을 거쳤다. 이 과정 자체가 이번 라운드의 발견 중 하나다.

| 회차 | 조건 | 결과 |
|---|---|---|
| 1차 | sonnet 본체, 기본 프롬프트 | **무효** — headless 세션이 빌더를 백그라운드로 띄운 뒤 종료해 미완주(`video.md` 없음, 41항목 전부 unaudited, 서브에이전트 8→2건) |
| 2차 | sonnet 본체, 완주 강제 프롬프트 | 완주는 성공했으나 **$13.96/57콜로 개선 전($11.12/27콜)보다 오히려 비쌈** — 완주 강제 문구가 폴링 루프를 유발해 턴 수가 팽창 |
| 3차 | **opus 본체**, 기본 프롬프트 (L2/L3 순수 효과 측정용) | 게이트 PASS(값 불일치 0, 지식 94% 유지, ⚠️ +0). 비용 $12.39 — 개선 전 대비 **+11%**. 빌더는 41콜→20콜로 줄었으나(-45%) 표본 감사가 6건→8건+재검 2건으로 늘어 상쇄를 넘어섬 (서브에이전트 8→13건) |
| 4차 (최종) | **opus 본체**, 기본 프롬프트, 전 레버(L2+L3) 적용 + 표본 3건 고정 | **채택된 결과** — $9.96, -10.4% |

**핵심 발견:** sonnet 본체는 서브에이전트를 백그라운드로 위임한 뒤 종료해버리거나(1차, 미완주), 완주를 강제하면 폴링으로 턴 수가 폭증한다(2차). opus 본체는 서브에이전트 완료를 동기적으로 대기해 27~38콜로 완주한다. 즉 **설계 문서의 L1 절감 추정치($7.20 → $1.44)는 "본체가 정상적으로 완주한다"는 전제 위에서만 유효**한데, 그 전제가 sonnet에서는 이번 실측 환경(headless 세션)에서 성립하지 않았다. `skills/tuto/SKILL.md`에는 sonnet 권장 문구가 여전히 안내로 남아 있지만(§0), **이 안내를 실제로 켠 상태의 비용 효과는 이번 라운드에서 검증되지 않았다** — 다음 라운드 과제로 남긴다.

## 감사 실효성 측정 결과 (이번 라운드의 핵심 발견)

표본 감사(고위험 지식 항목을 뽑아 독립 에이전트가 반박을 시도하는 단계)가 실제로 오류를 잡아내는지 정량 측정했다.

### 회고 집계 — 완료된 4편 재집계

| | 판정 건수 | evidence 수정 |
|---|---:|---:|
| 표본 감사 (4편 × 6건) | 24건 | **0건** |
| 커버리지 감사 (같은 4편) | — | **12건** 누락 회수 |

표본 감사는 지출은 확실했지만($1.23/편) 4편 24건 판정에서 evidence를 단 한 건도 수정하지 못했다. 반면 커버리지 감사는 같은 4편에서 누락 12건을 회수했다.

### 주입 오류 시험 — `docs/eval/inject-errors.py`

`evidence.json` 사본에 의도적 오류 6건을 주입해(상위 항목 `command`/`setting` 3건, 하위 항목 `concept`/`example` 3건) 표본 감사가 몇 건을 잡는지 측정했다.

- 표본 **6건** 체제: 주입 6건 중 **1건만** 표본에 포함
- 표본 **3건** 체제: 주입 6건 중 **1건만** 표본에 포함 (동일)
- **검출력이 동일** → 스펙 §3.4 판단 기준("3건 체제 검출 수 ≥ 6건 체제 검출 수 − 1") 충족 → **표본 감사를 3건으로 확정**

6건 표본으로도 주입 오류의 **1/6(17%)** 만 표본에 들어온다 — 표본 감사의 구조적 한계가 이번 시험으로 정량 확인됐다. 회고 집계(4편 24건, 수정 0건)와 일치하는 결과다.

### 결정론적 교차 대조 — `evidence.py` 신규 검사

같은 정규형의 값이 `visual_evidence`에 반복 등장하는데 문자열이 다른 경우를 LLM 비용 없이 flag하는 검사를 추가했다(§3.3). 이번 대상 영상에서는 **주입 오류 0건 검출**이었다 — 반복 등장하는 값이 거의 없는 영상이라 이 메커니즘 자체가 작동할 기회가 없었기 때문이다. 비용이 0이라 유지하되, **만능이 아니라는 것도 함께 기록한다.** 다른 영상 유형(수치가 여러 프레임에 반복되는 발표 자료 등)에서 재측정이 필요하다.

## 부작용: 본체 비용 +56%

`skills/tuto/SKILL.md`에 콜 수 통제 지시(L2)를 추가한 대가로 **본체(오케스트레이터)가 상주하는 컨텍스트 자체가 커졌다** — 콜당 `cache_read`가 82K → 101K로 늘었고, 본체 콜 수는 27 → 38(+41%), 실효토큰은 549,634 → 855,821(+56%)이 됐다.

서브에이전트(빌더) 쪽 절감은 -49%(1,382,095 → 698,126)로 컸지만, **본체 증가가 그 절감의 상당 부분을 되돌려줬다.** 순 효과가 -22.6%(실효토큰 기준)·-10.4%(달러 기준)에 그친 직접적인 이유다.

**교훈:** SKILL.md에 지시 문구를 추가하는 것 자체가 무료가 아니다. 본체는 매 콜마다 SKILL.md 전체를 다시 청구하므로, 서브에이전트 절감을 위해 추가한 지시가 본체 쪽 비용을 늘리는 상쇄 효과를 만들 수 있다. 다음 라운드에서 SKILL.md에 지시를 추가할 때는 본체 콜당 `cache_read` 증가분을 함께 측정해야 한다.

## 재현 명령

```bash
# 1. 개선 전(v0.3.3, master)과 개선 후(cost-round5) 각각 전용 세션(빈 디렉토리)에서 실행
claude -p "/tuto https://youtu.be/7MEsgHKQGLg" \
  --allowedTools "Bash Read Write Edit Glob Grep Skill Agent Task" \
  --output-format json

# 2. 비용 집계 (dedup + 실효토큰 가중치는 규약대로 자동 적용)
python docs/eval/measure-cost.py --marker 7MEsgHKQGLg --session <session-id> --project <project-dir>

# 3. 품질 게이트 — 두 evidence.json의 값 대조
python docs/eval/compare-evidence.py \
  --before <before-cache-dir>/evidence.json \
  --after  <after-cache-dir>/evidence.json

# 4. 감사 실효성 — 주입 오류 시험 (표본 3건 vs 6건 비교용)
python docs/eval/inject-errors.py --src <evidence.json> --out <injected.json> --n 6 --seed <seed>
```

⚠️ `--permission-mode dontAsk`는 자동 승인이 아니라 자동 거부다(Skill 도구까지 차단) — allowlist를 명시해야 한다. 본체 모델을 sonnet으로 바꿔 재현할 경우, 위 "측정 시행착오"에서 관측된 미완주/폴링 문제가 재현될 수 있으므로 완주 여부(`video.md` 생성, 서브에이전트 건수)를 반드시 확인할 것.

## Verdict

| 항목 | 결과 |
|---|---|
| 비용 목표 ($2.0~2.8) | **미달** — 실제 $9.96 (-10.4%만) |
| 콜 수 통제 (L2) | **성공** — 빌더 41콜 → 16콜 (-61%) |
| 표본 축소 (L3) | **성공, 근거 확보** — 검출력 손실 없이 6건 → 3건 |
| 본체 모델 티어 (L1) | **반증, 미채택** — sonnet 본체가 미완주/폴링으로 실측 불가능했음 |
| 품질 게이트 | **PASS (컨트롤러 재정)** — 도구는 서식 차이를 오탐, 실제 값 오독 0건 |
| 감사 실효성 | **측정 완료** — 표본 감사 회수 0건(4편 24건), 표본 건수를 6→3으로 확정할 근거 확보 |

**라운드 성과:** 이번 라운드의 진짜 성과는 "4~5.5배 절감"이 아니라 두 가지다. (1) 콜 수 통제만으로 서브에이전트 비용을 절반 가까이 줄일 수 있다는 것을 실측으로 증명했고, 그 절감이 본체 컨텍스트 증가로 상쇄될 수 있다는 것도 함께 발견했다. (2) 표본 감사의 실효성을 처음으로 정량 측정해 "6건 표본으로도 주입 오류의 1/6만 잡힌다"는 구조적 한계를 확인하고, 그 근거로 표본 건수를 절반으로 줄이면서도 검출력을 유지했다.

## 다음 라운드 과제

1. **L1(본체 sonnet) 재시도** — 이번 라운드에서 반증된 것은 "headless 세션 + 기본 프롬프트" 조건에서다. 백그라운드 위임을 막는 다른 방식(예: 명시적 동기 대기 지시, non-headless 세션)으로 재시도가 필요하다.
2. **본체 콘텍스트 증가 억제** — SKILL.md에 지시를 추가할 때마다 본체 콜당 `cache_read` 증가분을 측정 항목에 포함시킨다. 이번 라운드처럼 서브에이전트 절감이 본체 증가로 상쇄되는 것을 사전에 잡기 위함이다.
3. **결정론적 교차 대조를 반복값이 많은 영상에서 재측정** — 이번 영상은 반복 등장 값이 거의 없어 메커니즘이 시험되지 않았다.
4. **`compare-evidence.py`의 서식-차이 오탐 개선(신중히)** — 이번 라운드에서 기호/한글 혼용 표기 차이가 오탐을 냈다. 정규화를 넓히면 진짜 오독까지 흡수할 위험이 있으므로, 다음 라운드에서 사람이 재정한 사례를 더 모은 뒤 신중하게 접근한다.
5. **§3.5 R4 과제였던 D축(agent usefulness) 실행 및 사람 ground truth 확보는 여전히 미실행** — 라운드 1의 과제가 그대로 이월된다.
