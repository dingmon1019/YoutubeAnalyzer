# 화면 근거 보장 라운드 (grounding, v0.19.0 → v0.20.0) — 2026-08-22

## 왜 했나
v0.18.0 사후 점검에서 **화면을 읽고도 지식으로 만들지 않는** 구멍이 드러났다: 지식 60건 중
frame 인용 0건, 등재된 V 10건 전부 미인용. 그 결과 자막값이 화면값을 이겨 **정본에 틀린 설정값**이
실렸다(자막 "scale it down to 30" vs 화면 `Size 25` → 문서엔 30). watch 대비 차별점의 붕괴다.

원인 3겹: ① 계량 게이밍(하한이 생기자 값싼 재료=자막으로 채움) ② 커버리지 감사(텍스트 전용)가
화면 대조 없이 정본에 직행 ③ `cross_check_values`가 `visual_evidence` 내부만 순회(화면과 지식을
마주 놓는 코드 부재, 게다가 `_near_miss`는 편집거리 1이라 25↔30은 원래 못 잡음).

## 무엇을 했나
- **결정론 화면 검문 `screen_check`**: type이 `setting|command`인 지식·주장의 숫자 토큰을 ±90초
  창의 화면 관측과 대조 → 어긋나면 `screen_conflict` 표기 + 렌더에 `⚠️ 화면값 X (자막 Y)`.
  **본문 자동 치환 금지**(조용한 변조 금지). 모든 `--from-lines` 병합에 걸려 **커버리지 감사 경로도
  검문을 통과**한다.
- **정밀도 2연속 보정(컨트롤러 통합 검증에서 발견)**: ① 자릿수 일치 요건 — 실측 오탐 "해상도 2K의
  `2` vs 화면 `25`"가 거짓 경고를 렌더했다. 설정값 오독은 같은 꼴로 어긋난다(25↔30). 헛경고는
  v0.13.0에서 재확인 디스패치를 폐지시킨 바로 그 실패라 재현율보다 정밀도를 앞세웠다.
  ② **미등재 원본 관측까지 후보 풀로**(`screen_pool_from_cache`) — 1차 게이트가 드러낸 설계 구멍:
  선별 등재 이후 정본의 V는 인용된 것뿐이라 **지식과 어긋나는 화면 값일수록 등재되지 않아**
  검문을 빠져나간다. "원본은 캐시에 보존된다"는 선별 등재의 전제를 여기서 회수한다.
- **근거 인용 감지·1회 재합성**: 합성 응답에 `V 인용 j건` 추가 → j=0인데 V 관측 ≥10줄이면 1회 재합성,
  이후에도 0이면 진행 + `--note "화면 근거 미인용"`. 빈약 전사 감지와 동형(3번째 적용).
- **합성 계약**: 화면 구체값(설정값·UI 라벨·수치·파일명)은 자막이 말하지 않아도 K로 등재·`v#` 인용,
  자막≠화면이면 화면 채택 + `conflict=`. "하한을 자막만으로 채우지 마라".
- **K type 별칭 정규화**(지난 라운드 미해결): 커버리지가 낸 `font-setting` 등이 배치 전량 거부를
  일으키던 구멍. 드롭 대신 정규화 + `NORMALIZED` 보고.

## 남은 한계 (정직 기록)
**조밀한 설정 패널의 작은 글씨 판독 편차**: 같은 프레임의 Size 값이 회차마다 25·28로 갈리고, 한 회차는
아예 못 읽어 미판독 ⚠️ 8건을 냈다(다른 회차 1건). 검문은 "읽힌 값"만 대조할 수 있으므로 미판독은
구조적 미탐이다. 처방 후보: 설정 패널 감지 시 확대 해상도 상향 또는 패널 분할 크롭(zoom.py) —
비용 영향이 있어 별도 라운드.
