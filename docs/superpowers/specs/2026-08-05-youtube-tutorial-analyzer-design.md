# 유튜브 튜토리얼 분석 플러그인 설계 — yta (`/tuto`)

- 날짜: 2026-08-05
- 상태: 설계 확정 (A안 v2 + 품질 평가 체계 편입)
- 저장소: D:\Repository\YoutubeAnalayzer (그린필드)

## 1. 목적과 범위

**문제.** 유튜브 튜토리얼 영상(화면 따라하기형)을 기존 방식으로 분석하면 ① 자막만으로는
화면 정보(어떤 버튼, 어떤 설정값)가 통째로 누락되고 ② 프레임을 균등/씬컷으로 뽑으면 토큰이
중요하지 않은 곳에 낭비된다. 두 문제의 뿌리는 하나 — "어디가 중요한지 모른 채 균등하게
훑는다".

**목표.** 30분 이내 한국어/영어 튜토리얼 영상 1편을 ~60k 토큰으로 분석해 다음을 산출:

1. **따라하기 스텝 가이드** (1순위) — 시각·행동·설정값·근거 프레임 인용이 있는 재현 가능한 단계별 문서
2. **핵심 요약 노트** — 영상이 다루는 내용의 압축 요약
3. **Q&A 가능 상태** — 캐시 기반으로 후속 질문에 재다운로드 없이 답변

**제약.**
- Gemini API는 무료 한도 내에서만, 그것도 최후방 (v1에서는 미사용)
- 개인용 우선 (Windows 이 머신 기준). 구조는 공개 가능하게, 문서·설치 UX는 최소화
- ASR: Groq whisper-large-v3 우선 → 로컬 faster-whisper 폴백 (한국어는 large-v3급 필수)

**비범위 (v1).**
- 외부 노트 앱(Notion 등) 내보내기
- 30분 초과 영상의 완전 지원 (경고 + 구간 지정 제안으로 대응)
- Video-RAG식 로컬 OCR 텍스트 보강 (`--ocr` 옵션 자리만 예약, v2 후보)
- 골든셋 자동 평가 하네스 (절차만 문서화, 사용자 참여 필요)
- 공개 배포용 크로스플랫폼 지원·영문 문서

## 3. 아키텍처

### 3.1 플러그인 구조

```
YoutubeAnalayzer/
├── .claude-plugin/plugin.json          # 플러그인 매니페스트
├── skills/tuto/
│   ├── SKILL.md                        # /tuto <url> [질문] — 오케스트레이션 계약서
│   └── scripts/
│       ├── analyze.py                  # 패스 1: 지도 생성 (진입점, --cleanup 포함)
│       ├── zoom.py                     # 패스 2 확대 + 검증 패스 재확대 + Q&A 재확대
│       ├── signals.py                  # 히트맵·챕터·SponsorBlock·활동 곡선 수집
│       ├── transcribe.py               # 자막 → Groq → faster-whisper 3단 폴백
│       ├── frames.py                   # ffmpeg 추출 + dedup
│       └── setup.py                    # 프리플라이트 (ffmpeg/yt-dlp/키/버전 확인)
├── docs/superpowers/specs/             # 본 설계 문서
└── README.md
```

- 각 스크립트는 독립 실행 가능, stdout 보고서가 Claude와의 인터페이스
- 스크립트 간 통신은 **캐시 디렉토리를 통해서만** (직접 import 결합 최소화)
- Windows 우선: `python` 명령 사용 (`python3`는 MS Store 스텁)

### 3.2 캐시 레이아웃 — Q&A의 기반

```
~/.yta/cache/{video_id}/
├── video.mp4         # 720p 원본 (재확대용 유지)
├── transcript.json   # 타임스탬프 자막 + source 필드 (captions|groq|local|none)
├── signals.json      # 히트맵 100구간·챕터·SponsorBlock·활동 곡선
├── frames/           # 추출 프레임 (파일명에 t=MM:SS, 해상도 표기)
├── zoom-plan.json    # 확대 계획 (감사용)
└── guide.md          # 최종 산출물
```

설정: `~/.config/yta/.env` — `GROQ_API_KEY`, `CACHE_MAX_VIDEOS=10` (LRU), `SETUP_COMPLETE`

### 3.3 데이터 흐름 — 2패스 + 검증, 예산 ~60k

```
패스 1 「지도」 (~25k)
  signals.py   히트맵(InnerTube) + 챕터 + SponsorBlock + 활동 곡선   ~1k
  transcribe.py 자막 전문 (VTT 중복 제거 후)                        ~15k
  frames.py    512px × ~36장 — 활동 피크 ∪ 히트맵 피크 ∪ 챕터 시작점에
               가중 배치, 광고 구간 제외, dedup                      ~7k
       ↓
  Claude 판정 → zoom-plan.json:
    스텝 후보 목록 + 확대 구간 리스트 (커버리지 제약 적용)
    판정 기준: ① 자막 지시어 큐 ② 히트맵 피크 ③ 챕터 경계
              ④ 어떤 확대 구간에도 안 덮인 활동 피크 (맹점 방지)

패스 2 「확대」 (~30k)
  zoom.py --ranges "3:20-3:50,..." — 구간당 2fps, dedup, 구간 캡 20장
  설정값·코드·버튼명 구간만 --res 1024 (장당 ~790토큰, 512px는 ~197)
       ↓
  Claude 작성 → guide.md 초안 (스텝별: 시각·행동·설정값·근거 프레임 인용)

검증 패스 (~5k)
  초안의 모든 설정값·버튼명 주장에 근거 인용(t=MM:SS) 의무
  불확실 판독 → zoom.py로 해당 시점만 1024px 재확대
  여전히 불확실 → 추측 금지, "⚠️ 화면 확인 필요 (t=MM:SS)" 표기
       ↓
  표본 감사 (§8.1) → 감사 스탬프 부착 → guide.md 확정
```

**다운로드 해상도: 720p 고정.** 144p는 UI 텍스트 판독 불가, 1080p는 용량 대비 이득 적음.
720p에서 1024px 프레임 추출 시 설정값 텍스트가 대체로 판독 가능. 판독 불가가 반복되면
1080p 재다운로드를 문서화된 폴백으로 둔다.

**예산 가드.** 자막 18k 초과 → 챕터별 압축(전문은 캐시 보존, Q&A 시 참조). 확대 계획 예산
초과 → 1024px 구간부터 감축. 지도 품질은 불가침.

## 4. 컴포넌트 계약

| 스크립트 | 역할 | 입력 | 출력 |
|---|---|---|---|
| `setup.py` | 프리플라이트. ffmpeg/yt-dlp 존재·버전, 키 유무, faster-whisper 설치 여부 | `--check`(무음) / `--json` | 종료코드 + 상태 JSON |
| `analyze.py` | 패스 1 오케스트레이션: 다운로드→signals→transcribe→지도 프레임. **지도 예산 배분기 소유** (신호 가중 배치 계산, ~36장은 30분 기준·길이 비례) | URL, `--cleanup` | stdout 보고서 (상태 헤더 + 자막 + 신호 요약 + 프레임 경로) |
| `signals.py` | 4신호 수집. 활동 곡선 = 1fps 썸네일 16×16 그레이스케일 인접 차분 | video_id 또는 로컬 경로 | signals.json |
| `transcribe.py` | 자막 사슬. VTT 롤링 중복 제거, VAD, 반복 환각 필터 | video_id, `--whisper groq\|local`, `--no-whisper` | transcript.json |
| `frames.py` | 가중 배치 추출 + dedup. 지도/확대 공용 | 배치 계획(타임스탬프 목록), `--res` | frames/ + 경로 목록 |
| `zoom.py` | 패스 2·검증·Q&A 재확대. 캐시된 video.mp4에서 재다운로드 없이. **확대 예산 가드 소유** (구간 캡·글로벌 캡 강제) | `--ranges`, `--timestamps`, `--res` | frames/ + 경로 목록 |

## 5. 핵심 설계 결정과 근거

조사(2026-08-05)에서 확인한 문제와 논문 근거 기반 타파법. 상세 출처는 §12.

| # | 문제 | 타파법 | 근거 |
|---|---|---|---|
| P1 | 씬컷·균등 배치는 튜토리얼의 마이크로 액션(1–2초 클릭·입력, 작은 픽셀 변화)을 구조적으로 놓침 | **활동 곡선**: 1fps 썸네일 차분으로 "언제 화면이 변했나" 전체 곡선 생성 (ffmpeg 1회, 토큰 0). 지도 프레임을 신호 가중 배치 | GUI-World: MLLM은 수동 키프레임 없이 동적 GUI 콘텐츠에 실패 |
| P2 | 자막 주도 확대는 말 없이 진행되는 조작(BGM 시연 등)에 맹점 | 확대 후보 = 자막 지시어 큐 ∪ 미커버 활동 피크 | 동일 |
| P3 | 확대 구간이 한 곳에 몰리는 중복 낭비 | 커버리지 제약(스텝당 최소 1구간, 구간 캡) + zoom-plan.json 감사 출력 | AdaRD-key: relevance-only 선택은 유사 프레임에 예산 집중 |
| P4 | OCR 환각 — 그럴듯한 설정값을 지어서 읽음. 가이드에서 오값은 누락보다 나쁨 | 검증 패스: 인용 의무 → 불확실 시 재확대 → 그래도 불확실이면 "확인 필요" 표기, 추측 금지 | MME-VideoOCR: language-prior bias 실증. Think-Then-Verify: 가설→검증이 확신형 오류 감소. UI-Zoomer: 불확실성 기반 줌인 |
| P5 | Whisper가 BGM/무음에서 환각("시청해주셔서 감사합니다", 반복 루프 — 삽입 오류의 86%) | faster-whisper Silero VAD 기본 활성화, Groq 경로 무음 사전 분할, 반복 n-gram 붕괴 후처리 필터 | Whisper 환각 유도 연구, WhisperX VAD Cut&Merge |
| P6 | 한국어 자동자막 VTT 롤링 중복 + 무거운 토큰화로 지도 예산 초과 | VTT 중복 제거 필수 + 18k 초과 시 챕터별 압축 | watch 실측: 49분 자막 26.6k |
| P7 | 히트맵 부재(<5만뷰)·편향(하이라이트 몰림) | 약한 사전신호로만 취급. 폴백 사슬: 히트맵→챕터→활동곡선→균등. 활동곡선은 항상 생성 가능한 최후 방어선 | — |
| P8 | Claude 판정 단계의 실행 편차 | SKILL.md에 명시적 루브릭 + 한/영 지시어 큐 사전 + zoom-plan.json으로 감사 가능화 | — |
| P9 | 캐시 용량 (720p 30분 ≈ 150–300MB) | 기본 유지 + `--cleanup` + `CACHE_MAX_VIDEOS` LRU | — |
| P10 | yt-dlp 차단·PO token 변동 | 로컬 주거용 IP로 실행(클라우드 ASN 차단 회피). 프리플라이트에서 yt-dlp 버전 확인·업데이트 권고 | youtube-transcript-api 클라우드 IP 차단 사례 |

**기각된 대안.** VideoTree/VideoARM 계층 메모리(1시간+ 규모용, 30분엔 과설계), 완전 에이전틱
검색(실행 편차), Gemini 네이티브(무료 한도·preview·프라이버시, 최후방 유지).

## 7. Q&A 동작

분석 완료 후 세션 내 후속 질문은 컨텍스트에서 직접 답변(재실행 금지). 새 시각 디테일이
필요하면 `zoom.py --timestamps`로 캐시에서 즉시 추출. 세션이 바뀌면 guide.md +
transcript.json + signals.json을 다시 읽는 것으로 복원 (video.mp4가 LRU로 삭제된 경우
재다운로드 필요함을 안내).

## 8. 품질 평가 체계

전제: ground truth는 영상 그 자체이며, 검증 비용은 생성 비용과 비대칭이다 — 주장 1개의
확인은 프레임 1장 조회다. 인용 의무화(§5 P4)가 산출물을 감사 가능하게 만든다.

### 8.1 표본 감사 프로토콜 (v1 자동화)

가이드 확정 전, 주장(설정값·버튼명·순서) 중 무작위 K=10개를 **독립 컨텍스트**(서브에이전트
호출, 가이드 작성 컨텍스트와 분리)에서 재검증. 검증자는 가이드 본문 없이 "주장 + 인용
프레임"만 받고 반박을 시도한다 (자기 검증의 상관 오류 방지). 결과는 가이드에 스탬프로 부착:

```
📋 표본 감사: 10개 주장 중 9 일치, 1 불일치(수정됨) — 추정 오류율 ~10%
```

### 8.2 외부 GT 기회적 diff (v1 자동화)

크리에이터 제공 준-GT가 있으면 자동 대조: 설명란 스텝 정리·고정 댓글 타임스탬프 → "설명란에
있는데 가이드에 없는 항목"을 누락 후보로 보고. 챕터는 스텝 분할 정확도의 부분 GT로 상시 사용.

### 8.3 골든셋 회귀 기준 (절차만 문서화, 사용자 참여 필요)

사용자가 이미 따라해 본 튜토리얼 3–5편(한/영 혼합) 선정 → 플러그인 초안을 사용자가 교정해
레퍼런스 확정 (1회 비용) → 이후 파이프라인 변경 시 측정:

| 지표 | 정의 |
|---|---|
| 스텝 재현율 | 레퍼런스 스텝 중 놓친 것 |
| 스텝 정밀도 | 지어냈거나 불필요한 스텝 |
| 설정값 일치율 | 값 정확 일치 (최중요) |
| 타임스탬프 오차 | 스텝 위치 초 단위 오차 |

### 8.4 재현성 환류 (수동, 상시)

최종 품질 정의: **영상을 안 보고 가이드만 따라 해서 같은 결과가 나오는가.** 사용자가
따라하다 막힌 지점은 해당 영상+지점을 골든셋에 편입 — 실사용 실패 사례로 평가 기준이
단단해지는 루프.

### 8.5 정직한 한계 (가이드 헤더에 검증 범위 상시 표기)

① 표본 감사는 오류율 추정이며 K=10으론 희귀 오류를 놓칠 수 있다. ② 골든셋은 장르 편향이
있다 (AI툴 튜토리얼에 최적화 시 타 장르 미검증). ③ 프레임에 안 보이는 정보(영상 밖
사전지식이 필요한 스텝)는 어떤 검증도 못 잡는다.

## 9. 에러 처리 — fail-loud

모든 단계는 성공 시에도 상태를 보고서 헤더에 명시 (자막 출처, 신호 가용성, 프레임 수/드롭
수). 0건·빈 결과는 "정상"이 아니라 "의심 대상"으로 보고.

| 단계 | 실패 | 대응 |
|---|---|---|
| 프리플라이트 | ffmpeg/yt-dlp 부재 | winget/pip 명령 안내. yt-dlp 구버전 → 업데이트 권고 |
| 다운로드 | 로그인 필요·지역 차단 | 평문 보고 후 중단. 재시도 루프 금지 |
| 자막 사슬 | 각 단계 실패 | native→Groq→local 폴백, source 필드 기록. 전부 실패 시 프레임-only 진행 + guide 상단에 한계 명시 |
| Whisper 청크 | 부분 실패 | 부분 전사임을 표기 (조용히 이어붙이지 않음) |
| 신호 | 히트맵/챕터 부재 | §6 폴백 사슬. 챕터 없으면 자막 기반 스텝 경계 추정에 "추정" 표기 |
| 예산 | 자막/확대 초과 | §3.3 예산 가드 |
| 30분 초과 | — | 경고 + 구간 지정 제안. 강행 시 sparse 명시 |
| 검증 | 불확실 잔존 | "⚠️ 확인 필요 (t=MM:SS)" — 산출물의 정상 요소 (없는 게 오히려 의심 신호) |

## 10. 테스트 전략

| 레벨 | 대상 | 방법 |
|---|---|---|
| L2 단위 (pytest, 무네트워크) | VTT 중복 제거·히트맵 파싱·SponsorBlock 파싱·반복 환각 필터·예산 배분기 | 픽스처 JSON + ffmpeg `testsrc` 합성 클립 |
| L2 단위 | 활동 곡선 | 합성 클립(정지 5초+변화 1초+정지 5초)에서 피크 위치 검증 |
| L3 런타임 | analyze.py 전체 | 실제 짧은 튜토리얼 한/영 각 1편, 보고서 출력 직접 관측 |
| L4 E2E | /tuto 전체 흐름 | 힉스필드류 실영상 1편 → guide.md에 (a) 타임스탬프 스텝 (b) 인용된 설정값 (c) 검증 패스 흔적 (d) 감사 스탬프 실재 확인. 수동 체크리스트 (자동화 안 함) |

전역 규칙: "동작함" 주장은 L3+ 관측 증거가 있을 때만.
