# tuto 성능개선 라운드 1 — 설계 스펙

- 날짜: 2026-08-06
- 상태: 사용자 설계 승인 완료 (접근법 A), 스펙 리뷰 대기
- 절대 조건: **산출물 품질 저하 0** — §5 게이트 전부 통과 전에는 완료 선언 금지

## 1. 배경·기준선

같은 영상(zP3i_7xZW7Q, 16:11)으로 tuto와 watch v0.2.0을 실측 비교한 결과가 기준선이다
(상세: 프로젝트 메모리 `yta-watch-benchmark`).

| | tuto (기준선) | watch |
|---|---|---|
| 시간 | 17.3분 | 5.2분 |
| 실효 토큰 | 176만 (본체 99만 + 감사 77만) | 78만 |
| 품질 | 감사 10/10, ASR 오독 3건 교정 | 핵심 표 프레임 0장, 번역 자막 오염 |

비용 구조: 감사 서브에이전트 44%, 본체 신규 적재(cache_write) 72%(자막 이중 적재 포함),
zoom 5.5분(프레임당 ffmpeg 직렬 5.5초), cp949 재실행 낭비 1.7분.

## 2. 목표·지표

- **비용**: 달러 등가 실효 토큰 176만 → **100만 이하**.
  - 실효 토큰 = input + 2×cache_write + 0.1×cache_read + 5×output
  - 달러 등가 = 실효 토큰 × (해당 모델 input 단가 / 세션 모델 input 단가).
    공개 요금표 기준(Haiku 4.5 $1/M), 단가 미공개 모델(Fable)은 Opus($15/M)로 근사한다.
  - 측정: 세션 jsonl을 **message.id로 dedup** 후 합산 (블록 수만큼 중복 기록되므로 필수).
- **시간**: 17.3분 → **12분 이하** (같은 영상, 콜드 프레임 기준).
- **품질**: 비저하 절대 조건 — §5 게이트로 판정. 목표 미달 시 조용히 조정하지 않고
  보고 후 다음 레버를 논의한다(fail-loud).

## 3. 설계 결정

### D1. 감사 에스컬레이션 (SKILL.md §5)

- 표본 감사 서브에이전트 10개를 `model: haiku`로 실행한다.
- 판정 MATCH → 채택. **MISMATCH / UNVERIFIABLE → 그 주장만 기본(세션) 모델로 재검**,
  재검 결과를 최종으로 한다.
- 감사 스탬프에 "Haiku n건 판정 + 상위 모델 재검 m건"을 명시한다.
- **채택 게이트(오류 주입 시험)**: 벤치마크 프레임의 확정 주장 3개(원본) + 값을 변조한
  주장 3개를 Haiku에 감사시킨다. **변조 검출 3/3 미달 시 Haiku 포기** → Sonnet으로 동일
  시험 → 그것도 실패하면 이 레버 폐기(현행 유지). 잔여 리스크는 "틀린 주장의 오수용
  (false MATCH)"뿐이며 이 시험이 그 확률을 직접 측정한다.

### D2. cp949 근본 수정 (common.py + 스크립트 7개)

- 원인: `analyze.py:262`·`zoom.py:119`의 `sys.stdout.reconfigure(errors="replace")`가
  `encoding="utf-8"`을 지정하지 않아, 파이프 stdout이 Windows 로케일(cp949)로 인코딩됨.
  signals/frames/setup/transcribe는 가드 자체가 없음.
- 변경: `common.utf8_stdout()` 헬퍼 신설 — `sys.stdout`/`sys.stderr`에
  `reconfigure(encoding="utf-8", errors="replace")` (reconfigure 미지원 스트림은 무시).
  **7개 스크립트 main 전부** 첫 줄에서 호출.
- 효과: 재실행 1.7분 + 자막 이중 적재 재발 방지. SKILL.md의 `PYTHONUTF8=1` 우회 지시 불필요.

### D3. zoom 병렬화 (frames.py)

- 원인: `frames.extract_frames()`가 프레임당 ffmpeg 1프로세스를 **직렬** 실행 (5.5초/장).
  `dedup_frames()`의 `_thumb()`도 프레임당 ffmpeg 직렬 실행.
- 변경: `ThreadPoolExecutor`(워커 `min(8, os.cpu_count())`)로 ffmpeg 호출을 병렬화.
  - 추출 결과 수집은 **입력 타임스탬프 순서 유지** (제출 순서대로 수집).
  - 썸네일은 병렬로 선계산해 `_thumb_cache`에 채운 뒤, `dedup_frames`의 순차 비교
    로직(ref 체인)은 그대로 둔다.
- **불변식**: 산출 파일 집합·파일명·dedup 결과가 직렬 실행과 결정적으로 동일해야 한다.
- 예상: zoom 5.5분 → 1분 이내. analyze의 지도 프레임 추출도 같은 경로라 동반 단축.

### D4. 핀포인트 dedup 결함 수정 (zoom.py)

- 원인: `zoom.py` main(현행 148행 부근)이 `--ranges`/`--timestamps` 구분 없이
  `dedup_frames()`를 적용 → 명시 요청한 핀포인트 프레임(내용이 다른 문서 화면)이
  16×16 썸네일 비교에서 드롭됨. 파킹 목록 수정 후보 1순위.
- 변경: `--timestamps` 모드는 dedup을 건너뛴다 (추출된 전부 반환, dropped=0).
  `--ranges` 모드는 현행 유지. 판정 근거: 핀포인트는 "명시 요청 시점"이므로 전량 반환이
  계약에 맞다 (메모리 `yta-post-merge-followups` 판정 승계).
- 효과: frames.py 직접 호출(`--no-dedup`) 우회로 불필요해짐. SKILL.md 검증 절차의
  재확대 신뢰성 향상.

### D5. signals 재사용 (analyze.py)

- 원인: `run_pass1()`이 매 실행 `build_signals()`로 활동곡선(전체 영상 디코드)을 재계산
  → 캐시 히트 재실행도 102초.
- 변경: `signals.json`이 존재하고 **mtime이 `video.mp4`보다 새로우면** 읽어서 재사용,
  아니면 재계산 후 저장(현행). flags 포함 전체 sig dict가 저장되므로 STATUS 출력 불변.
- 효과: 품질 게이트 재실행·Q&A 재분석마다 ~1.5분 절약. eviction 후 재다운로드 시
  video.mp4가 새로워져 자동 무효화된다.

## 4. 변경하지 않는 것 (범위 외)

- 다운로드 포맷: 이미 `bv*[height<=720]` 캡 존재 (설계 중 확인된 정정).
- 자막 파일화·스크립트단 큐 매칭(접근법 B): 골든셋 구축 이후 재검토.
- 장르 분기(강의형 요약 중심), zoom `--timestamps` 상한: 이연 유지.
- 2패스 구조(접근법 C): 기각 — "말 없는 조작 방어"와 충돌.
