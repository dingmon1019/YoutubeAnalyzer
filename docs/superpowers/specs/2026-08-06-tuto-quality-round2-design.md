## 1. 배경

라운드1(v0.1.1)로 시간 -31%·비용 -33%·품질 비저하를 확정했다. 라운드2는 품질 증가가
목표이며, 사용자 제약은 "토큰은 유지·감소, 품질은 유지하며 증가". 리서치가 확인한 현
파이프라인의 최대 품질 결함은 **누락(recall)**이다 — 표본 감사는 "쓴 주장"만 검증하고
"빠뜨린 스텝"은 구조적으로 잡지 못한다. 부차 결함은 잔글씨·서식 변화 판독(Invisible
Mentor 오류분석: 볼드 텍스트 58.3%·글꼴색 변화 35.7% 누락 — 검증된 주장 clm_006).

## 2. 설계 결정

### Q1. 감사 예산 재배분 — 커버리지(누락) 감사 신설 (SKILL.md §5)

- 가치 주장 표본 10건 → **6건** (현행 Sonnet+크롭 프로토콜 유지).
- 6건 선정 규칙에 추가: **서식·상태 변화 주장(볼드/색상/토글/활성화 상태) 최소 1건 포함**.
  가이드 작성 규칙(§4)에도 "행동 결과로 나타나는 서식·상태 변화를 스텝에 명시"를 추가.
- **커버리지 감사 1건 신설** (Sonnet, 독립 컨텍스트): 입력 = 자막 전문 + 챕터 +
  DESC_TIMESTAMPS + **가이드의 스텝 제목 목록만** (본문 비공개 원칙 유지). 절차 =
  소스에서 "기대 스텝 체크리스트"를 먼저 생성 → 가이드 스텝 목록과 대조 → 누락 후보를
  `- [MM:SS] <내용> — 근거 자막 인용` 형식으로 반환 (TICK식 체크리스트 평가 [src_305][src_505]).
- 누락 후보 처리: 오케스트레이터가 프레임·자막으로 확인해 명백 누락이면 가이드에 스텝
  보강(1회 한정), 불확실하면 "누락 후보" 절에 기재. 재분석 루프는 돌지 않는다(토큰 상한).
- **자막 없는 영상**(no transcript 플래그)은 커버리지 감사를 스킵하고 스탬프에 명시 —
  체크리스트 원천이 없다.
- 스탬프 형식 확장: `📋 표본 감사: 6개 주장 중 n 일치 — Sonnet 6건 판정 + 재검 m건 /
  커버리지: 기대 스텝 k개 중 누락 후보 j건 (검증 범위: 설정값·버튼명·순서·서식변화·커버리지)`
- 토큰 판정: 커버리지 에이전트는 자막 입력으로 개당 가치 감사의 ~2.5배 → 총합
  ≈ 6 + 2.5 = 8.5 단위 vs 현행 10 단위. **순중립~감소.**

### Q2. OCR-우선 판독 (setup.py·frames.py 또는 신규 ocr.py + SKILL.md §2)

- setup: OCR 엔진 자동 검출 — **3단 사다리** (2026-08-07 사용자 결정, 배포 풋프린트 근거):
  1. **Windows 내장 OCR** (`Windows.Media.Ocr`, PowerShell 호출) — 추가 설치 0MB.
     한국어 언어팩 존재를 검출 조건에 포함(PowerToys Text Extractor와 같은 엔진).
  2. **Tesseract + kor.traineddata** (~100MB, `winget install tesseract` 원커맨드) —
     내장 OCR 미가용(비Windows·팩 부재) 시. OCRmyPDF(⭐32k)·pytesseract가 쓰는
     "시스템 바이너리 요구" 표준 관행이며 기존 ffmpeg·yt-dlp 패턴과 동일.
  3. 둘 다 없으면 기능 비활성 + `--check` stderr NOTE와 analyze STATUS flags에
     `ocr_absent` 명시(조용히 저하 금지).
  - PaddleOCR은 스펙에서 제외 — 설치 풋프린트 수백MB~1GB로 배포 부담 과대.
    **G2 전면 미달 시에만 재검토** 각주로 남긴다.
  - G2 게이트는 **검출된 엔진 그대로** 심판한다 (내장 OCR이 검출되면 내장 OCR로 실측).
- 추출 프레임의 OCR 텍스트를 산출해 보고서의 FRAME 라인 다음에
  `OCRTXT t=MM:SS: <정제 텍스트>` 로 출력. 프레임당 상한 300자(초과분 절단 표시).
  실패·저신뢰 프레임은 라인 생략(빈 값 출력 금지). 저신뢰 기준: 엔진 평균 confidence
  < 0.5 또는 인식 결과 공백 — 구현 시 엔진별 스케일에 맞춰 상수로 명문화한다.
- SKILL.md §2 해상도 루브릭 변경: "설정값·코드·메뉴 텍스트 구간이라도 **512 프레임 +
  OCRTXT로 값이 판독되면 @1024를 배정하지 않는다**. OCRTXT와 화면이 다르면 화면 우선
  (기존 검증 규칙과 동일 서열: 화면 > OCR > 자막)."
- **채택 게이트 G2 (레버 축소 조건)**: 벤치마크(zP3i_7xZW7Q)의 1024 프레임 13장과 같은
  시점의 512 추출+OCR을 대조 — 라운드1 감사를 통과한 값(금액·날짜·자격 수치) 기준
  **재현율 ≥95%** 미달 시, 1024 축소 규칙은 철회하고 OCRTXT 동봉만 유지(그 결과를
  스펙 이력에 기록). 한국어 스크린샷 OCR 정확도는 실측된 바 없으므로 게이트 없이
  루브릭을 바꾸는 것은 품질 절대 조건 위반 위험이다 [src_203 ScreenAI 방향 근거,
  수치는 자기보고 — Unresolved annex 참조].
- 토큰 판정: OCRTXT +~100토큰/장 vs 1024→512 전환 −589토큰/장(약 5:1). 게이트 통과 시
  **순감소**, 미달 시 +미미(동봉만이면 1024장수 불변 + OCRTXT 소량 증가 — 이 경우에도
  총액 상한 게이트로 관리).
- **G2 실측 결과 (2026-08-07, 전면 미달 — 레버 폐기):** 기준 ≥95%(25/26) 대비
  winocr 512 1/26·1024 4/26, tesseract 5.5.3+kor 512 3/26·1024 6/26,
  tesseract+2x 전처리(금액표) 1/10. 영상 압축 한글 잔글씨는 두 엔진 모두 판독 불가
  도메인 — VLM 직접 판독(값 95/95)이 우월한 증거원으로 실측 확정. 사용자 결정 A로
  OCR 계열 전체 롤백 (커밋 이력에 보존). PaddleOCR 재검토는 하지 않기로 함.

### Q3. 재확대의 크롭 대체 (zoom.py + SKILL.md 검증 규칙)

- zoom.py에 크롭 모드 추가: `zoom.py <id> --crop "<기존프레임파일명>@x,y,w,h"` —
  frames/ 의 기존 파일에서 ffmpeg crop(영상 재디코드 없음), 출력 파일명
  `<원태그>c<일련>_<res>.jpg`, FRAME 라인 보고. 존재하지 않는 원본 파일이면 평문 에러.
- SKILL.md 검증 규칙 변경: 재확대는 **기존 1024 프레임 크롭 우선**, 해당 시점 프레임이
  없을 때만 `--timestamps` 재추출. 세션 예산 가드에 "크롭 재질의 영상당 ≤5회" 추가.
- 근거: DiMo-GUI류 학습-없는 test-time zoom-in [src_204] (수치는 자기보고 — annex).
  라운드1 실측에서도 재검 에이전트 5/5가 크롭으로 판독 성공.
- 토큰 판정: 이미지 비용 동등 이하(크롭이 원본보다 작음), 스크립트 재추출 시간 제거.

### Q4. 골든셋 평가 체계 (docs/eval/ 프로토콜 문서)

- 사용자가 이번 라운드에 튜토리얼 3~5편 제공(2026-08-06 결정). 절차: 초안 가이드 생성 →
  사용자 교정 → 레퍼런스 확정 → 지표 산출.
- 지표 정의:
  - **스텝 재현율(R1-Recall)**: |레퍼런스 스텝 중 초안에 의미 매칭된 것| / |레퍼런스 스텝|.
    LLM 의미 매칭, many-to-one 허용, 타임스탬프 ±30초 내 정합 [src_506 DenseStep2M식].
  - **값 정확도(Value-F1)**: 레퍼런스 스텝의 설정값·버튼명에 대해 정규화(단위·쉼표·한글
    숫자 표기 통일 — 규칙은 평가 문서에 명문화) 후 토큰 F1 [src_507 Mind2Web Operation-F1
    이식]. 문헌에 값 의미동치 표준이 없어 정규화 규칙은 자체 정의임을 명시.
  - **보고 형식**: per-video 진단표만. n≤5로 통계적 일반화 주장 금지 [src_508][src_509].
    LLM 매칭 판정은 최소 1회 사용자 대조로 검증(LLM-judge 무검증 관행 경고).
- 이번 라운드 산출: `docs/eval/golden-set-protocol.md`(프로토콜) + 골든셋 1차 측정 기록.
  평가 러너 코드화는 라운드3로 이연(YAGNI).

## 3. 변경하지 않는 것 (범위 외)

- 계층 분할(30분+, VideoTree식) — 비용 배수 리스크, 라운드3 후보.
- SoM 오버레이 — 밀집 화면 한계 보고 + 전처리 복잡도.
- 프레임 예산 증량·다중 샘플 self-consistency — 토큰 증가형.
- 평가 러너 코드화, 2패스 구조 변경.

## 4. 게이트 (완료 조건)

1. **pytest**: 기존 93 + 신규(OCR 검출·비활성 분기, OCRTXT 출력 상한, crop 모드,
   crop 원본 부재 에러) 전부 통과.
2. **G2 OCR 게이트**: §Q2 기준 재현율 ≥95% — 미달 시 레버 축소를 스펙 이력에 기록.
3. **벤치마크 E2E**: (a) 값 95/95 동일 유지, (b) **누락 오류주입 시험** — 벤치마크
   가이드에서 스텝 1개를 고의 삭제한 스텝 목록으로 커버리지 감사 실행 → 해당 누락을
   검출해야 채택, (c) 분석 1회 달러가중 ≤ 라운드1 실측(117만) — message.id dedup 방법론.
4. **골든셋 1차 측정**: 제공 영상 3~5편의 R1-Recall·Value-F1 per-video 기록(라운드2
   품질 기준선 수립 — 향후 라운드의 회귀 기준).

## 5. 리스크·폴백

| 리스크 | 방어·폴백 |
|---|---|
| 한국어 OCR 정확도 미달 | G2 게이트 → 동봉만으로 축소 (전면 미달 시에만 PaddleOCR 재검토) |
| OCR 엔진 미설치 환경 | 3단 사다리 자동 강등 + flags 명시(현행 동작과 동일하게 저하) |
| Windows 내장 OCR의 PowerShell 호출 취약성 | 호출 실패 시 Tesseract로 자동 강등, 테스트로 검출 분기 고정 |
| 커버리지 감사가 자막 오류에 오염 | 누락 후보는 프레임 확인 후에만 보강, 불확실은 후보 기재 |
| 자막 없는 영상 | 커버리지 감사 스킵 + 스탬프 명시 |
| 골든셋 교정 지연 | 게이트 4는 영상 제공 시점부터 — 다른 게이트와 독립 진행 |
| 토큰 상한 초과 | fail-loud 보고 (라운드1 §5.4 선례) |
