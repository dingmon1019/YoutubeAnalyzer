# 함수형 서브에이전트 구조 (설계)

- 작성일: 2026-08-18 · 기반 브랜치: `code-render` (렌더러·--from-lines 재사용, 미병합 보류분)
- 사용자 요구: solo $2.91의 반값($1.5) 이하, API 키 요구 절대 금지(오픈소스 스킬 원칙), 대화형 세션 누적 구조 탈피.

## 0. 목표와 비목표

**목표:** `/tuto` 1편을 **2회 실측 평균 ≤$1.5** (내부 목표 $1.0~1.2, opus 세션)·**≤15분**으로. 방법: 무거운 내용물(이미지·긴 산출물)을 **일회용 서브에이전트**의 소멸하는 컨텍스트로 옮기고, 본체는 이미지 0장·긴 출력 0의 얇은 오케스트레이터로 만든다. 전부 Agent 도구(구독 과금) — **외부 API 키를 요구하지 않는다.**

**비목표:** 새 산출물·새 스크립트 대량 추가. evidence.json/video.md 계약, 렌더러·확장기·교차 대조·커버리지 감사는 그대로 쓴다.

## 1. 왜 이 구조가 앞선 세 번과 다른가 (실측 근거)

| 라운드 | 접근 | 결과 | 남긴 교훈 |
|---|---|---|---|
| R5 | 위임 유지 + 프롬프트 통제 | -10% | 본체가 다 든 채 루브릭 전문을 다시 써주면 이중 청구 |
| solo | 위임 제거, 본체가 전부 | $2.91 | 이미지·산출물이 본체에 상주, 콜마다 재청구 |
| code-render | 직렬화·렌더링 코드화 | $3.50 | 절감분을 LLM이 더 깊게 파는 데 재소비 |

공통 원인: **무거운 내용물이 대화 누적 컨텍스트에 상주**. 이 설계는 상주 자체를 없앤다 — 이미지는 haiku 컨텍스트에서 소멸하고, 지시문은 프롬프트 파일로 서브에이전트가 스스로 Read하며(본체 디스패치 출력 ~100토큰), 산출물은 디스크로 오간다(본체는 내용을 안 본다).

## 2. 파이프라인

```
1. analyze.py → 지도 프레임·자막                                [본체, 코드]
2. 비전① (haiku): prompts/transcribe.md Read → 지도 전량 병렬 Read
   → V라인(전사) + Z라인(확대 요청 시각) → vision-map.lines Write  [이미지는 여기서 소멸]
3. zoom.py <Z시각들@1024> && --add-frames                        [본체, 코드]
4. 비전② (haiku): 확대 프레임 전사 → vision-zoom.lines
5. 합성 (sonnet): prompts/synthesize.md Read → 자막 + vision*.lines(텍스트만)
   → patch.lines Write — V라인 전부 복사 + K/C/G (단일 배치)      [이미지 없음]
6. --from-lines patch.lines --cross-check                        [본체, 한 호출]
7. CROSSCHECK flag 시: 비전 재확인(haiku, 해당 프레임만) → 정정 보강
8. 커버리지 (haiku, 기존) → 보강
9. --render --cross-flags N --coverage-added M [--note ...]      [본체, 코드]
10. 요약 + 자연어 요청 계속                                       [본체]
```

**본체 규율:** 프레임 Read 절대 금지(솔로에서 유일하게 본체가 이미지를 보던 확대 판정을 비전①의 Z라인이 대체한다), patch/vision 파일 내용을 echo하지 않는다, 디스패치 프롬프트는 경로+한 줄 지시만(지시문은 프롬프트 파일에). 목표 12콜 이내, 초과해도 완주.

**id_offset 함정 회피(설계 확정):** 합성은 vision*.lines의 V라인을 **그대로 전부 복사**해 patch.lines 한 파일로 만들고 `--from-lines`는 **1회만** 호출한다 — 배치 간 v-id 참조가 생기지 않는다. vision*.lines는 중간 파일이며 직접 merge하지 않는다. (정정·보강 배치의 v#는 기존 규칙대로 해당 배치 신규 V만 참조.)

## 3. 프롬프트 파일 (신규 2개 — skills/tuto/prompts/)

- `transcribe.md` — 비전 전사기: 판단·요약 금지, 화면 문자열 그대로(오타 포함), 프레임 전량 한 응답 병렬 Read, 흐리면 `⚠️ 화면 확인 필요` + confidence low, 텍스트 없는 프레임은 V라인 생략. 지도 모드일 때만 Z라인(값 밀도 상위 3~4곳·자막 지시어 큐·60초 공백 1곳, **Z는 무조건 1024 대상**). 최종 응답 한 줄.
- `synthesize.md` — 지식 합성기: **이미지 Read 금지**, 자막+전사 텍스트만 근거, V 전부 복사 후 K/C/G(기존 TSV 규격, 행동 가능한 content, 화면 우선+conflict, 근거 없는 지식 금지). 최종 응답 한 줄.

프롬프트 파일도 계약이다 — 핵심 문구를 계약 테스트로 고정한다.

## 4. 게이트 (컨트롤러 실측)

1. **비용: 2회 실측 평균 ≤$1.5** (n=1 분산 실측 22↔35콜 교훈), 개별 회차 ≤$1.8
2. **$/지식항목 ≤$0.05** — 새 KPI (solo $0.083)
3. `command`·`setting` 오독 0건 — **전사 A/B**: 비전 haiku 전사를 solo-opus evidence(보존본)의 동일 프레임 값과 대조
4. 지식 항목 ≥28건, 시간 ≤15분
5. **haiku 전사 실패 시 폴백**: A/B에서 오독이 나오면 비전만 sonnet으로 올려 1회 재측정(+~$0.1) — 그래도 실패면 라운드 중단·보고
6. 실패 시 롤백: SKILL.md·prompts만 되돌리면 code-render 상태로 복원(스크립트 무변경이므로)

## 5. 하지 않는 것

- 외부 API 키·Batch API (오픈소스 스킬 원칙 위반)
- 본체의 프레임 판독 부활, 표본 감사 부활
- vision.lines의 직접 merge (id_offset 함정)
- sonnet 세션 실측은 이 라운드 범위 밖 — opus 게이트 통과 후 별도 옵션(통과 시 $0.5~0.7 가능성)
