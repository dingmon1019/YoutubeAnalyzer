# /tuto — 튜토리얼 영상 → 따라하기 가이드

`/tuto <video-url> [질문]` 호출 시 아래 절차를 그대로 따른다. 모든 주장(설정값·버튼명·순서)은
프레임 근거를 인용하고, 검증 패스와 표본 감사를 거친 뒤에만 사용자에게 제시한다.

**SKILL_DIR**: 이 SKILL.md가 위치한 디렉토리. 아래 모든 명령은
`python "<SKILL_DIR>/scripts/<script>.py"` 형태로 실행한다 (Windows 환경이므로 `python3`는
쓰지 않는다).

## 0. 프리플라이트 (세션 첫 호출만)

`python "<SKILL_DIR>/scripts/setup.py" --check`를 실행해 종료 코드를 확인한다.
- 0이면 다음 단계로 조용히 진행한다. 단, stderr에 yt-dlp 최신성 NOTE(stale 경고)가 있으면
  그 내용을 사용자에게 짧게 알린다 — exit 0이라도 stderr가 항상 비어 있는 건 아니다.
- 2면 stderr에 출력된 설치 명령을 그대로 사용자에게 안내한다.

## 1. 패스 1 — 지도

`python "<SKILL_DIR>/scripts/analyze.py" "<url>"`를 실행하고, 보고서의 STATUS 줄을 가장 먼저
확인한다. **Bash 도구 timeout은 600000(10분)으로 지정한다** — 다운로드·프레임 추출·dedup
썸네일링까지 합치면 기본 2분 제한을 넘기기 쉽다. zoom.py도 구간이 길거나 여러 개면 동일하게
timeout 600000을 지정한다.
- flags에 자막 없음(no transcript available)이 있으면 사용자에게 알리고 프레임 중심으로
  진행한다 (가이드 상단에 한계를 명시).
- 30분 초과 WARNING이 있으면 사용자에게 구간 지정을 제안하고 진행 여부를 확인한다.

보고서 마지막 `== CACHE ==` 줄의 경로가 `<cache_dir>`다 — 이후 zoom-plan.json·guide.md 저장 경로로 사용한다.

**패스1 보고서를 `<cache_dir>/pass1-report.txt`로 저장한다** (파일 리다이렉트로 직접 기록 —
`| head`·`| tee | head` 같이 파이프를 조기 종료하는 조합은 쓰지 않는다. 하류가 파이프를 닫으면
보고서가 잘린 채 exit 0으로 끝나 조용히 실패한다). 이 경로는 §2 판독 에이전트와 §4 빌더가 함께 쓴다.

**오케스트레이터는 프레임을 Read하지 않는다.** 지도 프레임 판독은 §2의 판독 에이전트가 수행한다
(비용 티어링 — 이미지가 오케스트레이터 컨텍스트에 들어가면 이후 모든 API 호출에 cache_write로
재청구된다. 실측상 본체 cache_write가 총비용의 최대 68%였다).

## 2. 확대 계획 판정 → zoom-plan.json (판독 에이전트 위임)

**지도 프레임 판독과 확대 계획 판정을 `model: "sonnet"` Agent(판독 에이전트)에 위임한다.**
오케스트레이터는 보고서의 텍스트(STATUS·자막·챕터·피크)만 보고, 프레임은 보지 않는다.

판독 에이전트 프롬프트에 다음을 담는다:
- `<cache_dir>` 경로와 `pass1-report.txt` 경로
- `== FRAMES ==` 아래 **모든 FRAME 경로 전량** (에이전트가 병렬 Read한다)
- 아래 "판정 루브릭" 전문과 zoom-plan.json 형식
- 산출 계약: `<cache_dir>/zoom-plan.json`을 Write한 뒤, **최종 응답으로 아래 4줄만** 반환
  1. `장르:` 한 줄 (조작 튜토리얼 / 슬라이드 설명형 / 실물 시연형 / 토킹헤드 위주 등 + 실제 UI 조작 유무)
  2. `프레임 공백:` 지도 프레임이 60초 이상 비는 구간 전부 (`MM:SS-MM:SS` 나열, 없으면 `없음`)
  3. `확대 배정:` 1024px N장 / 512px N장 — **`(텍스트 화면 M개 중 N개 1024)` 를 반드시 덧붙인다.**
     M은 루브릭 5의 "글자를 옮겨 적어야 하는 화면" 개수다. N < M이면 그 차이만큼 빌더가
     값을 못 읽는다는 뜻이므로, 상한(20장)에 걸린 게 아니라면 N = M이 되도록 다시 배정한다.
  4. `특이:` 오케스트레이터가 사용자에게 보고해야 할 관측 1~2줄 (없으면 `없음`)

**`프레임 공백`은 생략 불가다.** 튜토리얼의 검증·정리 구간은 화면 변화가 적어 프레임 선정에서
구조적으로 탈락하는데, 실측 2건에서 그 구간에 결론부가 통째로 들어 있었다 — 판독 에이전트는
공백을 찾아 보고하고 그 구간에 확대를 우선 배정해야 한다.

에이전트가 산출 계약을 위반하면(zoom-plan.json 미생성·4줄 미반환) **1회 재지시**하고, 재실패 시
오케스트레이터가 직접 프레임을 Read해 판정한다(위임 철회 — 감사 스탬프에 명시).

**오케스트레이터는 `확대 배정` 줄의 `N < M`을 확인한다.** 상한(20장) 때문이 아닌데 N이 M보다
작으면 1회 재지시한다 — 실측에서 판독 에이전트가 1024를 4장만 배정해(텍스트 화면은 그보다
많았다) 빌더가 크롭으로 메워야 했다. 1024를 아끼면 값을 못 읽는다.

**판정 루브릭 (판독 에이전트가 전부 적용 — 프롬프트에 이 블록 전문을 넣는다):**
1. 자막 지시어 큐가 있는 시점은 확대 후보다. 지시어 사전은 다음과 같다.
   - 한국어: "여기(를) 보시면/보세요", "이렇게", "이 부분", "클릭", "누르면/누릅니다", "선택",
     "설정", "입력", "들어가서", "이 값", "요기"
   - 영어: "look here", "as you can see", "click", "select", "notice", "right here",
     "this setting", "type in", "go to", "hit"
2. 챕터 경계마다 스텝 후보 1개 이상.
3. `== ACTIVITY_PEAKS ==` 중 어떤 확대 구간에도 덮이지 않는 피크는 반드시 구간 1개를 배정한다
   (말 없는 조작 방어).
4. 커버리지 제약: 모든 스텝 후보에 최소 1개 확대 구간. 한 주제에 구간을 3개 이상 몰지 않는다.
5. **해상도 배정 규칙 — 화면에 읽을 텍스트가 있으면 1024, 없으면 512.**
   - **1024**: 슬라이드 본문·표·조건식·코드·터미널 출력·메뉴 항목·다이얼로그·설정 패널 등
     **글자를 옮겨 적어야 하는 화면 전부**. 여기서 아낀 1024 한 장이 빌더의 `⚠️ 화면 확인 필요`
     한 줄이 된다.
   - **512**: 삽화·전환 연출·토킹헤드·타이틀 카드처럼 **읽을 텍스트가 없는 화면**.
   - 판단이 갈리면 1024로 올린다. 512로 내려서 얻는 절감보다 값을 놓치는 손실이 크다.
6. 예산: 1024px 확대는 총 20장, 세션 전체 확대 프레임(재확대·Q&A 포함)은 60장이 **상한이다.**
   상한은 목표가 아니다 — 남기려 애쓰지 말고, 규칙 5에 해당하는 화면이면 상한까지 채운다.
   텍스트 화면이 20장을 넘으면 값 밀도가 높은 쪽(표·조건식·수치)부터 채우고 나머지는 512로
   내린 뒤 그 사실을 `특이`에 적는다. (§3.3 토큰 예산 가드 — zoom.py 1회 호출 내부 캡과
   별개로, 세션 누적치는 판정하는 쪽에서 직접 추적해야 한다.)

판정 결과를 `<cache_dir>/zoom-plan.json`으로 저장한다 (Write):

```json
{
  "steps": [
    {"idx": 1, "title": "프로젝트 생성", "t_start": 65, "t_end": 190}
  ],
  "zooms": [
    {"range": "1:05-1:35", "res": 1024, "reason": "설정 패널 값 입력"}
  ]
}
```

## 3. 패스 2 — 확대

`python "<SKILL_DIR>/scripts/zoom.py" <video_id> --ranges "1:05-1:35@1024,4:10-4:40"`로
zoom-plan.json의 구간을 확대 추출하고, **출력된 FRAME 경로 목록만 기록한다 — 확대 프레임의 판독은 §4의
가이드 빌더가 수행한다** (오케스트레이터가 여기서 프레임을 Read하면 비전 비용이 이중으로 발생한다).

**오케스트레이터는 파이프라인 전 구간에서 프레임을 Read하지 않는다** — 지도는 §2 판독 에이전트,
확대는 §4 빌더, 검증은 §5 감사가 각각 자기 컨텍스트에서 본다. 유일한 예외는 §2·§4의 위임이
2회 실패해 철회된 경우다.

**정적 슬라이드 위주 영상은 `--ranges` 대신 `--timestamps`를 쓴다.** zoom.py의 구간 표본화는
`count = min(20, 초×2fps)`라 10초 구간에서 20장을 뽑는데, 정지 화면에서는 같은 이미지를
20번 받는 셈이다. 지점 지정이 같은 정보를 훨씬 싸게 얻는다.

## 4. 가이드 초안 → 검증 패스

가이드 작성은 **`model: "sonnet"` Agent(가이드 빌더)에 위임**한다 (비용 티어링 — 스펙 R3 T1. 값 판독력은 감사 실측으로 검증된 티어이며, 품질은 §5 감사와 값 대조가 심판한다). 빌더 프롬프트에 다음을 담는다:
- 캐시 디렉토리 경로와 **kept FRAME 경로 전부**(지도+확대), 그리고 §1에서 저장한 `<cache_dir>/pass1-report.txt` 경로 — 자막·챕터·DESC_TIMESTAMPS가 빌더의 텍스트 증거다
- 아래 "형식" 목록과 "검증 규칙" 4개의 **전문**
- 재확대 수단: `python "<SKILL_DIR>/scripts/zoom.py" <id> --crop "<프레임>@x,y,w,h"` (호출당 5건 이내 — 코드 캡 있음)
- 산출 계약: `<cache_dir>/guide.md` 작성(감사 스탬프 자리는 "(표본 감사 후 기입)") 후 **최종 응답으로 §5 규칙에 맞는 표본 주장 후보 6건(검증형 주장이 6개 미만이면 전부 — 억지로 채우지 않는다)**(서식·상태 변화 ≥1건, 해당 범주 부재 시 "서식변화 주장 없음" 명시)을 주장 1문장+근거 프레임 절대경로로 반환

빌더가 산출 계약을 위반하면(guide.md 미생성·섹션 누락·후보 미반환) **1회 재지시**하고, 재실패 시 오케스트레이터가 직접 작성한다(위임 철회 — 감사 스탬프에 명시). 오케스트레이터는 빌더 완료 후 guide.md의 형식(헤더·요약·스텝·스탬프 자리)을 확인하고 §5 감사로 진행한다. 감사 MISMATCH의 가이드 교정은 오케스트레이터가 수행한다.

`<cache_dir>/guide.md` 형식:
- 헤더: 제목·URL·길이·자막 출처·검증 범위를 명시한다.
- `## 요약` (5줄 이내)
- `## 준비물` (영상이 전제하는 도구·계정)
- `## 스텝 N: <제목>` — 본문에 행동과 설정값을 적는다. **모든 설정값·버튼명에는 근거 인용
  `(t=MM:SS)`가 필수다.**
- `## 감사 스탬프` (5단계에서 채운다)

**검증 규칙 (환각 방지 철칙):**
1. 프레임에서 또렷이 읽히지 않는 값은 쓰지 않는다. **재확대는 기존 확대 프레임의 크롭
   우선**: `python "<SKILL_DIR>/scripts/zoom.py" <id> --crop "t1234d5_1024.jpg@x,y,w,h"`
   (좌표는 읽으려는 영역). 해당 시점의 1024 프레임이 없을 때만
   `--timestamps "12:34@1024"`로 재추출한다. **크롭 재질의는 영상당 5회 이내.** 크롭이 대상 영역을 다 담지 못했으면 크롭 결과로 "없음"을 결론하지 말고 **원본 프레임을 재확인**한다.
2. 재확대 후에도 불확실하면 그 값 자리에 `⚠️ 화면 확인 필요 (t=MM:SS)`라고 표기한다. 추측 금지.
3. 자막이 말한 값과 화면의 값이 다르면 화면을 우선하고, 불일치는 각주로 남긴다.
4. **표·목록·다이어그램은 화면의 칸을 그대로 옮긴다.** 셀이 비어 있거나 아이콘만 있으면
   `(아이콘만)`이라고 적는다. 자막에서 얻은 이름·번호는 표 안이 아니라 표 아래
   `자막 출처: …` 줄에 적는다. — 규칙 3은 자막과 화면이 *다를* 때를 다루고, 이 규칙은
   화면에 *없는* 칸을 자막으로 메우는 경우를 다룬다. 실측 사례: 3단계 요약표의 2·3행은
   화면에 아이콘만 있는데 빌더가 자막에서 "2. 입장"·"3. 예매"를 가져와 표에 채워 넣었다.
   **선명한 프레임을 받을수록 이 실수가 늘어난다** — 흐린 프레임은 크롭해 뜯어보느라
   빈칸을 알아채지만, 잘 읽히는 프레임은 술술 읽으며 메우기 때문이다.

## 5. 표본 감사 (Agent 서브에이전트, 독립 컨텍스트)

빌더가 반환한 후보(6건, 미만이면 전부)를 사용하되, 후보가 §5 규칙에 어긋나면 오케스트레이터가 직접 재표집한다 — 화면녹화 튜토리얼에서 서식·상태변화 주장(볼드/색상/토글/활성화)을 최소 1건 포함해야 하기 때문이다. 가이드에 해당 범주의 주장이 하나도 없으면 생략하고 스탬프에 '서식변화 주장
없음'을 명시한다. **가이드 본문은 주지 않고** 주장 하나와 근거 프레임만 독립된 Agent
서브에이전트에 보낸다.

감사 에이전트는 **`model: "sonnet"`으로 실행**한다. 판정이 MATCH면 그대로 채택하고,
**MISMATCH 또는 UNVERIFIABLE이면 그 주장만 기본(세션) 모델의 Agent로 같은 프롬프트를
재검**해 재검 결과를 최종 판정으로 삼는다 (비용 절감 레버 — 불확실성은 전부 상위
모델로 올라가므로 잔여 리스크는 오수용뿐이며, 이는 오류 주입 시험으로 게이트한다):

> "주장: <스텝 텍스트 1개>. 근거 프레임: <frame 경로>. 이 프레임을 Read하고 주장을 반박하라.
> 판독이 어려우면 ffmpeg로 해당 영역을 크롭·확대해 다시 Read하라 (임시 파일은 시스템 임시
> 디렉토리에 주장별 고유 파일명으로 — 병렬 감사끼리 crop.png 따위 공용 이름을 쓰면 서로 덮어쓴다). 그래도 판정 불가면 UNVERIFIABLE."

불일치로 판정된 주장은 가이드 본문을 수정하거나 `⚠️` 표기로 강등한다.

**커버리지 감사(누락 검출, 1건):** 별도 Sonnet Agent에 자막 전문·챕터·DESC_TIMESTAMPS와
**가이드의 스텝 제목 목록만** 보낸다(본문 비공개):

> "아래 소스에서 시청자가 따라해야 할 '기대 스텝 체크리스트'를 먼저 만들어라. 그런 다음
> 가이드 스텝 목록과 대조해 체크리스트에는 있으나 가이드에 없는 항목만
> `- [MM:SS] <내용> — 근거: <자막 인용>` 형식으로 반환하라. 없으면 'none'."

반환된 누락 후보는 프레임·자막으로 직접 확인해 **명백한 누락이면 가이드에 스텝을 보강
(1회 한정)**하고, 불확실하면 "누락 후보" 절에 기재한다. 재분석 루프는 돌지 않는다.
STATUS flags에 자막 없음(no transcript available)이 있으면 커버리지 감사는 스킵하고 스탬프에
명시한다 — 체크리스트 원천이 없다.

결과는 이 형식의 스탬프로 남긴다:

`📋 표본 감사: 6개 주장 중 6 일치 — Sonnet 6건 판정 + 상위 모델 재검 0건 / 커버리지: 기대 스텝 12개 중 누락 후보 1건 (검증 범위: 설정값·버튼명·순서·서식변화·커버리지)`

## 6. 외부 GT diff

`== DESC_TIMESTAMPS ==`는 §5의 커버리지 감사 입력에 이미 포함되므로 별도 대조를
반복하지 않는다. 커버리지 감사가 스킵된 경우(자막 없음)에만 여기서 DESC_TIMESTAMPS와
가이드 스텝을 직접 대조해, 설명란에는 있지만 가이드에는 없는 항목을
`- [MM:SS] <내용> — 근거: 설명란 타임스탬프` 형식으로 "누락 후보" 절에 보고한다.

## 7. 사용자 응답

가이드 전문을 채팅에 요약해 제시한다 (스텝 제목 + 핵심 값 위주). guide.md 파일 경로를
안내한다. 사용자가 `/tuto` 호출 시 질문을 함께 줬다면 그 질문에 먼저 답한다.

## Q&A (후속 질문)

이미 컨텍스트에 있는 프레임과 자막으로 먼저 답한다. analyze.py 재실행은 금지한다. 새로운
시각 정보가 필요할 때만 `zoom.py --timestamps`로 추가 프레임을 확보한다. zoom.py가
`ERROR: video.mp4 evicted ...`를 출력하면 캐시에서 영상이 밀려났다는 뜻이므로, analyze.py
재실행이 필요함을 사용자에게 안내한다.
